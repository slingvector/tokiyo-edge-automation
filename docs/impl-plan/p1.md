# Zero-Trust Distributed Edge-Automation Fleet

The goal of this project is to build a robust, zero-trust edge automation fleet powered by Android edge agents and a central orchestrator. 

This plan integrates the original roadmap from the `project-plan.md` along with the risk-driven "fail-fast" strategy defined in the supplementary documents, ensuring we validate physical constraints (Shizuku stability, IPC latency, battery optimizations) before building out the full architecture.

## Research Findings: Shizuku API Development

Based on web research, utilizing the Shizuku API introduces significant operational challenges that directly align with our "fail-fast" concerns:
*   **Binder IPC Complexity:** Shizuku exposes system APIs over Binder. We must actively manage the `addBinderReceivedListener` and `addBinderDeadListener` to gracefully recover from `DeadObjectException` without crashing. 
*   **Background Process Termination:** Android OEMs aggressively kill background processes. The Shizuku daemon itself is prone to being killed (e.g., by the PhantomProcessKiller). Battery optimization must be set to "Unrestricted" for both our Agent app and the Shizuku app.
*   **Port Drift:** Wireless debugging ports change on reboot. Running the Shizuku Binder engine as an independent `app_process` (User Service) mitigates reliance on a constant ADB network connection post-boot.
*   **Thread Blocking:** `bindUserService` can hang. We must handle bindings asynchronously via Coroutines to prevent UI thread blocking.

> [!CAUTION]
> If Shizuku IPC connection drops and fails to recover headlessly, the entire edge node architecture is compromised. Phase 0 is mandatory.

## Proposed Changes

### Phase 0: The Shizuku Stress Test (Throwaway Sandbox)

We will build a temporary Android application to validate the physical layer. 

#### [NEW] `shizuku-spike-sandbox/`
*   **App Setup:** Basic Android Studio project configured for Android SDK 34.
*   **Shizuku Integration:** Implement the Shizuku API (`moe.shizuku.privileged.api`).
*   **Connection Resilience:** Implement `Shizuku.addBinderReceivedListener` and `Shizuku.addBinderDeadListener` to test reconnecting when the daemon is manually killed via `adb shell am force-stop`.
*   **Latency Benchmark:** Write a loop executing `uiautomator dump` and `input tap` 50 times to measure base execution latency.
*   **Headless Test:** Setup a lightweight HTTP server in the app to ping the Shizuku connection over 24 hours to test `PhantomProcessKiller` limits.

### Phase 1: Edge Kernel & Privileged IPC (Core Architecture)

Once Phase 0 passes, we will scaffold the actual Clean Architecture project.

#### [NEW] `:core:domain` & `:core:crypto`
*   Define entities, use cases, and `AppResult` error monads.
*   Implement `ISecurityEngine` for Ed25519 payload verification.

#### [NEW] `:data:ipc`
*   Implement `IShellExecutor` wrapping Shizuku shell commands.
*   Implement `ShizukuBinderManager` utilizing lessons from Phase 0 to manage Binder states.

#### [NEW] `:data:telemetry`
*   Implement `IFlightRecorder` to gzip and base64-encode UI dumps on failure (`ERR_UI_NOT_FOUND`).

### Phase 2: Dynamic Perception & Execution Engine

#### [NEW] `:feature:perception`
*   **Tier 1:** `ISemanticPerceptionStrategy` to parse XML dumps and map coordinates. Includes the "Double-Pass DOM Validation" for SDUI latency mitigation.
*   **Tier 2:** `IVisualPerceptionStrategy` using ML Kit OCR as a fallback.

#### [NEW] `:feature:execution`
*   Implement `ITouchDispatcher` with human-like entropy (Gaussian random offsets, non-linear swipe velocity).
*   Implement `IClipboardInjector` (using the selected ADB Keyboard or Shell Stream strategy) to bypass Android 10 clipboard walls.
*   Implement aggressive sandbox cleanup (forcing app stops in `finally` blocks).

---

### Phase 3 & 4: Zero-Trust Bridge & Resiliency

#### [NEW] `:app` (Android Edge Node)
*   **FCM Ingestion:** `FirebaseMessagingService` to receive and validate signed JSON payloads.
*   **Doze & Thermal Management:** Intent checks for battery optimization and `ACTION_BATTERY_CHANGED` receivers to reject jobs if $>42^\circ\text{C}$.
*   **Periodic Worker:** 15-minute heartbeat to check Shizuku status and broadcast telemetry.

#### [NEW] `orchestrator/` (Backend - Go or Node.js)
*   PostgreSQL + Redis Queue architecture.
*   Cryptographic signing service (Ed25519) to sign payloads before FCM dispatch.
*   Circuit breaker logic handling `ERR_CHECKPOINT` and `ERR_UI_NOT_FOUND`.

## Verification Plan

### Manual Validation (Phase 0)
*   Deploy the Throwaway Sandbox APK to the physical device.
*   Kill Shizuku manually (`adb shell am force-stop moe.shizuku.privileged.api`) and verify the app reconnects.
*   Review logs for the 50-loop `uiautomator dump` execution to establish standard deviation latency.
*   Run the device headless overnight to verify survival against the Phantom Process Killer.

### Automated Testing (Phase 1-4)
*   **Coverage:** JaCoCo strictly enforcing $\ge$95% line and branch coverage across all Kotlin modules.
*   **Cryptographic Verification:** Pass/fail tests for valid, tampered, expired, and future timestamps.
*   **Fallback Sequence:** Mock UI failing XML parse and successfully recovering via ML Kit OCR coordinates.
