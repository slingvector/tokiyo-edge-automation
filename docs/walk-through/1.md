# Phase 0 Complete: Shizuku Stress Test Sandbox

I've successfully created the `shizuku-spike-sandbox` Android project to validate the highest risk elements of the architecture before proceeding to the clean architecture and back-end integration.

## What Was Built
*   **Android Scaffolding:** Initialized a lightweight project with Gradle setup for Kotlin Coroutines, Shizuku API (`13.1.5`), and Ktor (for our headless HTTP server).
*   **Shizuku IPC Resilience:** `MainActivity.kt` now implements `OnBinderReceivedListener` and `OnBinderDeadListener` to gracefully handle the Shizuku daemon crashing or disconnecting without crashing our app.
*   **Latency Benchmark:** Implemented a Coroutine-powered loop that triggers `uiautomator dump` and `input tap` 50 times sequentially. This will measure the absolute lowest latency the Shizuku IPC bridge can handle on your Samsung device.
*   **Headless Test Server:** Bootstrapped an embedded Ktor HTTP server running on port `8080`. This will allow your Mac to ping `/ping` every 45 minutes to test whether Android's `PhantomProcessKiller` destroys the Shizuku connection when the phone is locked.

## Deployment & Verification Instructions

You can now open the project in Android Studio, sync, and deploy the APK to your test device.

1.  **Open Project:** Open the `shizuku-spike-sandbox` folder in Android Studio. Gradle will automatically sync and download the wrapper.
2.  **Build & Install:** Run the app on your test device.
3.  **Bootstrap Shizuku:** Run `adb shell sh /sdcard/Android/data/moe.shizuku.privileged.api/start.sh` from your Mac terminal to start the daemon (or start it manually via the Shizuku app).
4.  **Run the Benchmark:** Tap the "Run Latency Benchmark" button in the app and monitor the log output to verify execution time.
5.  **Run the Phantom Process Killer Test:** Lock the device, leave it alone, and periodically run this from your Mac terminal:
    ```bash
    curl http://<PHONE_IP>:8080/ping
    ```
    If it replies `Shizuku Active: true` after 4-8 hours of screen-off time, the `PhantomProcessKiller` limit has been successfully bypassed.
